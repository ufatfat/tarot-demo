# 月见 MOONLIT

一个完整的塔罗互动游戏。深色夜空、古金色版画插画、洗牌与翻牌动效，以及由真实 AI 生成的解读与连续追问。

## 启动

需要 Node.js 22.12+（已在 Node.js 24 上验证）。

```sh
npm install
npm run dev
```

打开 **http://127.0.0.1:4178**。修改端口可以使用 `PORT=4180 npm run dev`。

```sh
npm run build  # TypeScript 检查与前端生产构建
npm start      # 使用构建后的静态页面，仍绑定本机地址
npm test       # 洗牌、牌阵、提示词、响应校验及 API 测试，无真实 AI 请求
```

## 玩法

- 78 张完整牌组：22 张大阿尔卡那与 56 张小阿尔卡那。
- 每张牌都有独立的 1024×1536 插画，统一采用深蓝与古金色版画风格，用于抽牌、解读和图鉴；牌名与边框由页面绘制，原图不含文字。
- 四种牌阵：每日一签、时间之流、关系之镜、选择之门。
- 选择关注方向、填写问题，也可以使用牌阵的默认问题。
- 使用浏览器密码学随机数进行 Fisher–Yates 洗牌，每张牌独立分配正逆位；同一次洗牌不会重复抽中同一张牌。
- 六组牌可自由切换，选中的牌再次点击即可取消，确认后可以逐张翻开或全部翻开。
- 解读先直接回答用户的问题，再展示单牌依据、牌阵综合、具体行动与反思问题。
- 解牌后可以连续追问，AI 每次都会带上原始问题、全部牌与正逆位、最初解读和本次全部已完成对话。
- 最近 50 次成功解读和各自的追问记录保存在当前浏览器，可回看、继续追问和删除；未完成的翻牌状态和最近一次解读也能在刷新后恢复。
- 图鉴支持按牌组筛选、中文/英文/关键词搜索，提供每张牌的正逆位参考。
- 原创循环配乐《月下回声》，以及洗牌、选牌、翻牌、解读、追问等 17 种操作音效；音乐和音效可分别调节音量。

## 声音

点击右上角「开启声音」开始播放，旁边的箭头可调整背景音乐和操作音效的音量。首次进入默认静音，开关和音量会保存在当前浏览器。刷新后需要再次点击页面或进行键盘操作才能播放；切到后台自动暂停，回来后从原位置继续。

《月下回声》长约 1 分 47 秒，72 BPM、4/4 拍、32 小节，以轻柔的竖琴、毡音键盘、钟声和铺底和声营造夜晚的氛围。音符与混响尾音跨越循环边界衔接，播放器负责淡入、淡出。音乐和全部音效均为本项目原创编曲与程序合成，没有使用第三方录音或采样。

| 操作 | 声音 |
| --- | --- |
| 普通按钮、切换标签 | 轻触短音 |
| 打开 / 关闭弹窗 | 上行 / 下行双音 |
| 洗牌 | 交错的纸张摩擦声 |
| 选牌 / 取消选择 | 明亮 / 下落的拨弦 |
| 确认选牌 | 纸牌落定与和弦 |
| 翻一张 / 全部揭晓 | 纸张翻动与钟声 / 展开的琶音 |
| 发起解读或追问 | 轻盈的上行提示 |
| 解读 / 追问完成 | 钟声和弦 / 简短回应音 |
| 取消请求、重新开始、删除记录 | 各自的轻收尾音 |
| 出错 / 保存成功 | 柔和提醒 / 双音确认 |

浏览器使用 Web Audio 播放本地 Ogg Opus，解码不支持时回退到 MP3；资源仅在开启声音后加载。重复操作有间隔限制和最多六个音效声部，并通过压缩器减小叠加时的音量突增。音频失败不会中断游戏。

音轨、清单和乐谱位于 `public/audio/v1/`。如需修改作曲并重新生成，安装带 `libopus`、`libmp3lame` 的 FFmpeg，再运行以下命令（已用 Python 3.9、NumPy 2.0.2、SciPy 1.13.1 验证；正常玩游戏不需要这些依赖）：

```sh
python3 -m venv .local/audio-venv
.local/audio-venv/bin/pip install numpy scipy
.local/audio-venv/bin/python scripts/compose_audio.py
```

脚本包含旋律、和弦和音色设计，生成两种发布格式；无损母带保存在被 Git 忽略的 `.local/audio-masters/`。

## AI 接入

连接 **OpenAI 兼容的 Chat Completions 接口**。页面右上角「AI 设置」可填写服务地址、模型名和 API Key。模型需要支持 `response_format: { type: "json_object" }`、`max_tokens` 和 system 消息。

也可以复制 `.env.example` 为 `.env` 后设置：

```dotenv
AI_BASE_URL=https://your-provider.example/v1
AI_MODEL=your-model-name
AI_API_KEY=your-key
```

服务端请求路径为 `${AI_BASE_URL}/chat/completions`，页面保存配置时也兼容粘贴完整的 `/chat/completions` 地址。环境变量在服务启动时优先于本地保存的配置。

密钥不会发送给浏览器，不会写入前端构建或 localStorage。页面设置保存在 `.local/ai-config.json`，文件权限为 `0600`，目录及 `.env` 已加入 `.gitignore`。配置界面只在开发模式下允许写入；生产模式使用环境变量或已有的本地配置。

没有配置 AI 时，仍可正常提问、抽牌、翻牌和查看图鉴。解读不会用固定文案冒充 AI 结果；接好服务后可以直接解读保留的牌。

提示词位于 `server/prompt.ts`：

1. 服务端根据牌 ID 重建牌名、牌位、正逆位和参考牌义，不信任客户端提供的牌义。
2. 将用户问题作为 JSON 数据，与 system 提示词分开。
3. 按「直接回答问题 → 单牌依据 → 综合解释答案 → 小行动 → 反思问题」输出结构化 JSON。新增的解读必须包含 `answer`，没有答案的模型响应会被拒绝；已有历史记录继续保留原始的整体观察，不冒充新生成的答案。
4. 强调象征性自我探索，避免宿命论、读心断言、恐吓和高风险确定性建议。
5. 校验响应结构、牌数、牌 ID 与顺序；失败、超时、额度不足、密钥错误都明确显示，并保留本次牌面以便重试。
6. `/api/readings/follow-up` 接受原始占卜资料、初始解读、按顺序排列的已完成对话及最新追问，返回 `{ answer, model }`。服务端重新补齐权威牌义，并验证初始解读与原牌一致。
7. 每个追问最多 500 字，每次占卜最多保留 24 轮追问；范围内发送完整上下文，不悄悄丢弃前文。失败或取消时保留输入，不把未完成回复保存为一轮对话。

## 目录

- `src/App.tsx`：游戏流程、图鉴与历史记录。
- `src/components/CardArt.tsx`：插画牌面、金色边框、SVG 牌背及图片加载失败时的线稿回退。
- `src/illustrations.ts`：已接入的插画清单与资源路径。
- `public/tarot/illustrated-v1/`：内置生图工具逐张绘制的 PNG 插画、`manifest.json` 清单和 `prompts.md` 提示词记录；图片从本地提供，按需加载。
- `src/styles.css`：桌面和手机布局、翻牌与洗牌动画、减少动画偏好适配。
- `src/storage.ts`：浏览器记录的读取、校验与恢复。
- `src/audio/`：声音加载、播放、音量、后台暂停及操作音效分发。
- `src/components/AudioControls.tsx`：声音开关和独立音量控制。
- `scripts/compose_audio.py`：原创配乐与 17 种音效的合成脚本。
- `shared/tarot.ts`：牌组、牌阵、参考含义与随机洗牌。
- `shared/validation.ts`：前后端共用的数据校验。
- `server/api.ts`：兼容接口调用、超时、并发和频率限制、错误清洗。
- `server/prompt.ts`：解牌提示词。
- `server/follow-up-prompt.ts`：连续追问的提示词与上下文组装。
- `src/components/FollowUpConversation.tsx`：追问输入、对话展示、取消和重试。
- `tests/`：单元和接口测试。
